# 效果识别与组件索引

基础表基线：2026-11-04；2026-11-06新增模板观察详见[十组交接](ten-demo-handoffs.md)，不要据此扩大整类能力的测试范围。证据代码：**官**=官方教程；**界**=当前编辑器核对；**桌**=桌面临时预览实际操作；**待**=尚需目标设备验证。组合方案若没有专门实测，不能继承子组件的“已实测”结论。

只有日常语言描述时，先用[视觉描述路由](visual-intent-routing.md)判别动作、高度与状态。多层轮播、聚光探索、手势判定、组合壁纸等特色需求见[20类高级结构](advanced-patterns.md)和[50篇案例](distinctive-svg-cases.md)，其来源研究不增加本表的实测等级。

## 先看这六个问题

| 观察点 | 直接影响 |
|---|---|
| 不操作也在动，还是点击/长按/滑动后才动？ | 自动播放、交互动画或普通滚动 |
| 动作后下面的正文被推下去了吗？ | 真展开与覆盖层显示的区别 |
| 手指能停在任意中间位置吗？ | 原生滑动与一次性动画的区别 |
| 能在同一位置反复切换、回退、重来吗？ | 单次转场、轮换、重复展开或重置 |
| 出现黑色全屏背景和保存图片动作吗？ | 可能是微信原生看大图 |
| 不同按钮导向不同内容，还是同一序列下一张？ | 分支路由与图集轮播的区别 |

## 机制说明的表述边界

只有截图时可说“这个外观可以通过重叠布局复现”；不能声称已看到作者源码。确实观察到生成的 `<svg>`、`<animate>`、`<animateTransform>` 时，才描述该样本的SVG实现。普通滑动使用滚动容器；图文排版并不需要也不能笼统依赖自定义JavaScript。
