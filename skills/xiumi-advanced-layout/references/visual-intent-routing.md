# 从用户的话到可执行的效果

目的：让用户说自己的话，智能体承担解释与选型。先理解整句和上下文，再检索[口语词典](spoken-effect-dictionary.json)；需要技术做法时才读[高级结构](advanced-patterns.md)。面向用户不输出内部分类编号或整套分析字段。

## 先确定“谁怎么动”，不要先找术语

把已知要求整理成一个简短的工作记录即可，缺项保留未知：

- **对象与范围**：里面的车、外面的框、一张卡还是整组。代词沿用最近一次明确对象；实在有两个候选才问。
- **触发与控制**：点一下、按着、手指拖着、滚动整篇或自动；中途能否停住。
- **前后状态**：从哪里到哪里、什么出现或消失、正文有没有被推下去。
- **先后与保留**：先A再B、同时、点过的保留、第二次收回、完成全部后才显示。
- **目标产物**：只展示、能改字、保存整图、答题结果、后台记录。

“其他不动”“不要自动”“别关回去”是约束，不是可忽略的修饰。“我说的是里面的图”修正作用对象，其他已确认要求继续有效。不要遇到一个新词就丢掉此前要求，也不要把用户拒绝的效果重新加回去。

### 处理模糊话的顺序

1. 从对话、现有稿和参考中找答案；不要问已有答案。
2. 如果不影响结构，采用可调的起始值并说明，例如“先让它轻一点地放大，幅度可以再改”。
3. 如果会改变结构，只问一个具体区别，用画面而非术语：“你是想让下方正文被推下去，还是在原位置露出另一张图？”
4. 等待时可准备共同素材或检查现有模板。必须知道答案才能定的部分，不能自行宣称已完成。可默认的装饰选择不用卡住整个任务。
5. 参考无法打开时明确目前能看见什么；截图只能判断外观，不证明手势。录屏只证明展示过的路径。

## 同一句口语的决定性区别

| 用户说法 | 决定性线索 | 内部选择 | 对外怎么说 |
|---|---|---|---|
| 慢慢出来 | 原位越来越清楚／从旁边进来／正文变长 | 透明度／移入／展开 | “在原位置逐渐看清”／“从右边滑进来”／“把下面正文慢慢推开” |
| 像抽屉一样 | 抽屉下拉并撑高／从侧面盖过来 | 高度展开／位移覆盖 | “往下拉开一段内容”／“从旁边滑出一个面板” |
| 点一下露出来 | 封面不见／封面保留并增正文 | 遮挡消失／新增高度 | “揭掉封面看到底图”／“封面下面展开正文” |
| 翻一下 | 平面转角／绕轴看背面／进入下一页 | 转动／翻面／页转场 | “原地转一下”／“翻到卡片背面”／“翻到下一页” |
| 点哪个开哪个 | 已开的不关／同时只能开一个 | 独立状态／互斥切换 | “每格各管各的”／“开新的一格时上一格收起” |
| 划开 | 划一下自动播完／松手即停 | 触发动画／连续手势 | “划一下，它自己打开”／“你拖到哪，它开到哪” |
| 擦亮、拿手电找 | 光走后保持亮／移走又暗／固定小洞看大图 | 定向显露／移动光源／视窗滑动 | 分别描述结果，不能都说“聚光探索” |
| 滑动 | 整篇文章走／小框里面走 | 文档滚动／局部滑动 | “页面正常往下读”／“页面不变，只移动框里的图” |
| 往上滑 | 手指向上／画面中的人上升 | 输入方向／物体位移 | 明说“手指向上推时，图片向上移动”或实际观察到的关系 |
| 一张张叠过去 | 自动定时／点一下换一张 | 自动图集／点击推进 | “不操作也会换”／“每点一次只换一张” |
| 比背景慢一点 | 每轮仍对齐／长期各走各的 | 同周期分阶段速度／独立周期 | “字晚一点跟上，但一直对应同一张照片” |
| 放大看细节 | 整张图变大／多个景别切换／微信看大图 | 缩放／配对序列／原生图片查看 | 说明是框内放大还是进入看图界面 |
| 立体、像电影 | 仅是风格感受／明确绕物体自由转 | 素材与构图建议／三维能力核对 | 先给建议，不能把“电影感”自动判为3D轮播 |
| 线长出来 | 光点沿线走／线本身逐段出现 | 路径移动／描线或序列素材 | “小点沿线跑”／“线从起点一点点画出来” |
| 拼完再出现 | 所有目标完成／任何一个触发 | 聚合条件／独立触发 | “全部找到后才出现结果”／“点中一个就会显示” |
| 换装后存下来 | 保存各张原图／保存当前拼成的整图 | 原生查看／合成导出 | “保存你刚搭好的整张图”需单独验证 |
| 输入密码 | 预设按钮顺序／键盘任意输入与鉴权 | 页面路由／表单或业务系统 | 不把有限点击故事说成安全登录 |
| 回到开始 | 重置组件／整篇滚动到顶 | 页面状态／锚点能力 | “这组卡重新开始”／“文章回到最上面” |
| 固定在上面 | 固定在这个框内／整篇阅读时一直吸顶 | 夹层固定／页面吸顶 | 先判范围，不能承诺公众号吸顶 |
| 弹窗 | 系统黑底看图／自定义文字按钮窗 | 图片查看／自定义层 | 根据内容和关闭方式选，不能当成同一能力 |

没有决定性线索时，词典里的专业名只是候选。技术路由允许“未知”与“新组合”，不要为凑20类而硬分。

## 风格要求怎样落地

“高级一点、别太花、丝滑、像杂志、电影感”先作为视觉偏好：留白、字体层级、色彩、动效幅度与节奏。只在用户确实要求动作时配置交互。

例如：“你想要画面更安静、动得轻一点。我先把装饰减掉，让照片缓慢靠近；如果你说的电影感主要指黑边或色调，也可以只改画面。”这是建议，不能冒充原话已明确指定镜头推进。不要因此追加用户没要的音乐、自动视频或外链H5。

## 六个回答样例

以下都是**表达与判断示例，不是本次已创建草稿或已核实菜单的报告**。真实交付需把通用素材位置换成当前稿的实测位置，详见[换图指南](image-replacement-guide.md)。

### 1. “点哪张开哪张，点过的别关回去，别一整排都跟着变。”

“每张卡都可以单独点开，打开后一直留着，其他卡不受影响。我会先做两张验证，再扩成整排。”

做法：每张卡分别放封面和打开后的内容；先点左卡再点右卡，检查左卡是否仍打开。用户没说要翻面，不擅自加翻转。

换图说明示例：“以后换左边卡片的照片，进入这张卡的编辑页，选中打开后看到的那张图再从‘我的图库’选新图；如果封面也有同一人物，封面那张也一起换。保留卡片大小和点击区域，换完依次点两张看看。”内部：独立局部状态；RIMG02。

### 2. “像抽屉那样拉开，不过下面的字别被挤走。”

“这个面板会在原来的区域里滑出来，下方正文保持原位。”已有否定约束，不再追问是否需要撑高。

做法：固定显示区域，把可移动面板放在里面，边框单独保留；核对面板是否遮住用户要保留的内容。

换图说明示例：“换抽屉里的照片时，只选面板里面那张图；外面的框和触发按钮保留。先按原比例换图，再预览它收起和滑出的位置。”内部：固定视窗内移入；RIMG02/RIMG04。

### 3. “那个图慢慢出来就行。”

若上文无更多信息：“你想要它在原位慢慢变清楚，还是从旁边慢慢滑进来？”不先输出三页专业方案。如果上文已说“车从右边开进来”，直接沿用右侧移入，别重复问。

可以先检查待替换图片和背景；目前没有定稿就说“换图入口确认后会随成稿给出”，不能编造“第三页第2层”。内部：渐显/移入待判。

### 4. “不是点一下播完，我手指停在哪里，它就开到哪里。”

“明白，要由你的手指控制进度，松手就停在当前位置。我会先检查模板能不能停在一半，再接后面的内容。”

没有实测证据时不承诺普通SVG淡出能做到。底图和盖在上面的图分别准备、保持同尺寸；若只能做自动播放，明确只是近似，不能替用户悄悄降级。内部：连续手势；RIMG07/RIMG08。

### 5. “字比照片慢一点，但不要出现这张图配了上一张的字。”

“照片先走，文字稍晚跟上，但每轮都对应同一张照片。”先只做两组，检查连续三轮与最后一组回第一组。

换图说明示例：“照片和对应文字要按同一个顺序改；只换第2张照片就同时检查第2段文字。别单独多加一张照片，否则两边会错位。保持两组总时长一致。”内部：同周期多层图集；RIMG03/RIMG10。

### 6. “框别动，里面的车跟着手指走。再把车换成我这张。”

“只移动框里的车，外框保持不动；我会把车图换成你给的这一张。”范围和后续素材指向都已明确。先检查新图是否透明、画布是否匹配；若新图是整张海报，先说明是否需要抠图，不能连边框一起替掉。

换图说明示例：“进入移动内容那层，选原来的车图再替换；如果车会伸出框外，要一起换外侧那张透明车图。透明图片保留整张画布，不要自动裁掉周围空白。”内部：固定前框＋局部滑动；RIMG06。

## 最后复核表达

读者不用查术语，能否说清“什么动、怎么触发、何时停”？流程是否给了真正要选中的对象？“你自己怎么换图”是否对应这次作品？只把完成路径称作实测，不把案例讲解或桌面实验说成所有手机通过。发现语言误判时补入[回归用例](intent-regression-cases.json)，不写未经测量的识别准确率。
